# ArtisanPack UI PageSpeedInsights Changelog

## [Unreleased]

### Added

- `Api\PageSpeedClient` — client for `runPagespeed`, with the credential resolution order API key → OAuth bearer token from a connected `artisanpack-ui/google` account → refuse. The third tier throws `MissingApiKeyException` **before** sending, rather than spending 20–60 seconds on a request Google's zero-quota anonymous project is guaranteed to reject. The API key travels on the `X-goog-api-key` header rather than the documented `key=` query parameter (both verified working live), so it never reaches a URL: Guzzle appends the full request URI to its connection-error messages, which puts a URL-borne key straight into exception reports and logs. `PageSpeedApiException` additionally redacts any `key=` or `access_token=` it finds in a transport message, for applications that point `endpoint` at a URL with one embedded.
- `Api\PageSpeedRequest` — validated url / strategy / categories / locale value object. Always sends an explicit `strategy` (the API defaults to desktop) and repeats the `category` parameter once per category (omitting it returns performance only), translating the lower-kebab response spelling to the upper-snake request enum on the way out.
- `Api\PageSpeedResponse` — the raw-to-DTO parser. Tolerates unknown categories, absent requested categories, missing lab metrics, and missing CrUX data; logs a warning naming the exact key it skipped in every case, and carries the same information onto the result so a thin run can be explained rather than guessed at. Lighthouse's own `runWarnings` are parsed rather than dropped, and a 200 carrying `lighthouseResult.runtimeError` becomes a typed failure preserving the original code and message.
- `Data\ScoreSet`, `Data\LabMetrics`, `Data\FieldData`, `Data\Opportunity`, and `Data\TestResult`. `ScoreSet` keeps typed accessors for the four scored categories while retaining any category Lighthouse adds later; `LabMetrics` covers the five metrics behind the performance score and deliberately omits Time to Interactive, removed in Lighthouse 10.
- `Exceptions\PageSpeedApiException`, `Exceptions\QuotaExceededException`, and `Exceptions\MissingApiKeyException` — three types for three causes, each with an `isRetryable()` posture and a message naming the fix rather than the status code. An unkeyed 429 maps to `MissingApiKeyException`, not `QuotaExceededException`: keyless PSI returns the same status as genuine quota exhaustion, and reporting the first as the second is what makes a never-configured install look like a broken queue.
- Opportunity pruning to `opportunities_limit` (default 10), ordered by estimated saving, with the `ap.pageSpeed.opportunities` filter applied before returning. A filter that returns something other than a list of `Opportunity` instances is ignored and logged rather than obeyed. Identifying an opportunity in Lighthouse 13 needs more than a non-empty `metricSavings`: Lighthouse attaches that to diagnostics and informational audits too, so a page scoring 100 would otherwise report a handful of "opportunities" worth zero milliseconds each. The parser skips the `notApplicable` / `informative` / `manual` / `error` display modes, skips passing audits, and requires a positive estimated saving. Verified against the live API — a page scoring 100 yields none, one scoring 95 yields two.
- `Data\FieldData::PERCENTILE` — the CrUX percentile is **75**, resolved against live keyed responses on 2026-08-02. The API discovery document's claim that v5 carries pc90 is stale; locating each reported value within its own `distributions` buckets bounds the percentile rank it must represent, and across 20 real metrics every bound was consistent with p75 while 8 were incompatible with p90. Labelling a p75 as a p90 would have been a silent correctness bug in every UI built on this.
- `Support\CategoryTranslator` for the request/response category spellings, and `Support\GoogleConnectionResolver` for the OAuth fallback.
- `PageSpeedInsights::client()` and `PageSpeedInsights::test()` on the package entry point.
- `config/pagespeed-insights.php` gains `endpoint`, `categories`, `timeout`, and `opportunities_limit`.
- Checked-in PSI fixtures in `tests/fixtures/` — healthy, poor (origin fallback plus more opportunities than the limit), no CrUX field data, a Lighthouse 13 response carrying `AGENTIC_BROWSING` with `seo` absent, a `runtimeError` result, and a quota error body. No test in the package calls the live API.
- `Contracts\ApiKeyRepository` — the storage contract for the PageSpeed Insights API key (`getApiKey()`, `save()`, `isConfigured()`). Because keyless PSI requests carry a daily quota of zero, `isConfigured() === false` is documented as a hard blocker callers should short-circuit on rather than a soft warning.
- `Configuration\ConfigDriver` — reads `PAGESPEED_API_KEY` / `config( 'pagespeed-insights.api_key' )`. Read-only; `save()` throws a `RuntimeException` naming the drivers that can persist a key.
- `Configuration\DatabaseDriver` — stores the key in the new `pagespeed_configurations` table, encrypted with the framework `Encrypter`, with a per-request cache and a `flush()` escape hatch. An undecryptable value logs a warning and degrades to unconfigured instead of throwing.
- `Configuration\CmsSettingsDriver` — stores the key via the CMS framework's Settings module under `artisanpack_pagespeed_api_key`. Encryption lives in the sanitize callback registered by the service provider, so both the driver and the Settings UI write the same ciphertext shape.
- `config/pagespeed-insights.php` with the `api_key` and `driver` keys, published under the `pagespeed-insights-config` tag. The comments state that an API key is required and that there is no supported keyless mode.
- `pagespeed_configurations` migration, loaded automatically and publishable under the `pagespeed-insights-migrations` tag.
- Driver selection via `PAGESPEED_CONFIG_DRIVER` (default `config`), bound in the service provider so the configured driver is re-read on each resolve, plus `PageSpeedInsights::config()` for reaching the active repository.
- Package scaffold generated from `package-blueprint`, following `artisanpack-ui/google-search-console` as the closest sibling reference.
- `composer.json` — `ArtisanPackUI\PageSpeedInsights` PSR-4 namespace, MIT license, `php ^8.2`, `illuminate/support ^10.0|^11.0|^12.0|^13.0`, and required `artisanpack-ui/core`, `artisanpack-ui/hooks`, `artisanpack-ui/google`, and `guzzlehttp/guzzle` dependencies. `suggest` entries for `livewire/livewire`, `artisanpack-ui/cms-framework`, and `artisanpack-ui/livewire-ui-components`.
- `PageSpeedInsightsServiceProvider` with the `pagespeed-insights` singleton binding, auto-discovered by Laravel.
- `PageSpeedInsights` facade and `pageSpeedInsights()` helper, both resolving the same container instance.
- Code style toolchain — `.php-cs-fixer.dist.php` and `phpcs.xml`, with `lint`, `fix`, `cs`, `cs:fix`, and `test` composer scripts.
- Pest + Orchestra Testbench setup with a base `TestCase` and coverage of the boot, binding, facade, and helper paths.
- CI workflow running lint plus the test matrix across PHP 8.2–8.4 and Laravel 12–13, and a release workflow that publishes to Packagist on tag.
- `docs/psi-api-reference.md` — PSI API endpoint, parameter enums, response schema, quota behaviour, and Lighthouse scoring, verified against the live discovery document and a live API probe on 2026-08-01. Records two findings that change the plan: keyless requests now carry a daily quota of **zero**, so an API key is effectively required rather than merely recommended; and the `category` enum has gained `AGENTIC_BROWSING` while `PWA` is deprecated, confirming the parser must tolerate unknown and absent categories.
